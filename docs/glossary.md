# Glossary

| Term | Meaning in this course |
|---|---|
| Artifact | Immutable build/package output promoted between stages |
| Attestation | Evidence tying an artifact to its build inputs and process |
| Blue-green | Separate deployment targets with controlled traffic switching |
| Canary | Small exposure before broader release |
| CalVer | Date-based versioning with an explicitly defined format |
| DORA metrics | Delivery indicators such as lead time, deployment frequency, change failure rate and recovery time |
| Environment | A deployment boundary with authorization, checks, and history |
| Feature flag | Runtime control that separates deploying code from exposing behavior |
| Federation | Trust that exchanges a short-lived workload assertion for scoped access |
| Idempotence | Repeating an operation produces the same intended state |
| KQL | Kusto Query Language for time-series/log investigation |
| OIDC | OpenID Connect; used for workload identity assertions in pipelines |
| Progressive delivery | Increasing exposure while measuring health and retaining rollback |
| Provenance | Traceable origin and transformation history of an artifact |
| RBAC | Role-based access control at a specific scope |
| Residual | An active managed object remaining after cleanup |
| SemVer | Major/minor/patch version semantics for compatibility |
| Trunk-based development | Short-lived branches integrating frequently into the main line |
| WIF | Workload identity federation, avoiding stored deployment credentials |
