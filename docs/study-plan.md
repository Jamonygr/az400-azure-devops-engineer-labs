# Study plan

Use four weeks for a concentrated review or eight weeks for deliberate practice.
Allow additional time for unfamiliar application, Git, or identity concepts.

| Week | Labs and review | Evidence to retain |
|---|---|---|
| 1 | 00–03: readiness, traceability, metrics, communication | Linked work/change records and reproducible metric calculations |
| 2 | 04–06: branching, administration, recovery | PR policy decisions and recovery rehearsals |
| 3 | 07–10: packages, tests, CI on both platforms | Versioned artifacts and failed/passing test reports |
| 4 | 11–13: reuse, agents, environments | Template contracts, isolated agent design, approval boundaries |
| 5 | 14–16: releases, rollback, feature flags | Release/rollback evidence and database compatibility reasoning |
| 6 | 17–19: IaC, configuration, maintenance | Bicep validation, scoped what-if, and pipeline optimization comparison |
| 7 | 20–23: permissions, identities, secrets, scanning | Least-privilege decisions and redacted scan/remediation evidence |
| 8 | 24–27: observability and capstones | Query results, incident diagnosis, validated cleanup |

After each assessed lab, answer its 50 questions before opening `ANSWERS.md`.
Scores below 70% indicate tasks to repeat; 70–84% warrants targeted remediation;
85%+ with independently completed practice indicates readiness to move on.
These are course study thresholds, not Microsoft exam scoring rules.

Repeat the deterministic break/fix without reading its repair first. For
capstones, explain why each platform-specific implementation satisfies the same
delivery requirement. Recheck the [official study guide](https://learn.microsoft.com/en-us/credentials/certifications/resources/study-guides/az-400)
before scheduling an exam because objectives may change.
